Проведи ревью кода. Работай только на чтение: ничего не меняй, не форматируй, не
устанавливай пакеты и не применяй правки. Если для проверки гипотезы нужен запуск —
опиши его в отчёте как рекомендацию.

Аргумент команды: $ARGUMENTS

## Область проверки

Определи режим строго по аргументу:

1. **Пусто** — текущие изменения: `git status --short` и `git diff HEAD`. Новые
   (untracked) файлы из `git status --short` читай напрямую: `git diff` их не показывает.
2. **`last`** — последний коммит: `git show HEAD` (при необходимости `--stat`), затем
   окружающий код затронутых файлов.
3. **`all`** — весь `src/` и `test/`.
4. **Существующий путь** (файл или папка) — только он. Существование проверь через
   `glob`/`read`; если пути нет, не выдумывай файлы — сообщи об этом и перейди к поиску.
5. **Любое другое слово или фраза** — поиск по `src/` и `test/`, например
   `git grep -n -i -- "<слово>" -- src test`, затем ревью найденных мест вместе
   с окружающим кодом. Если поиск пуст, попробуй `grep`/`glob` и явно скажи, что
   ничего не найдено.

Для чтения используй `read`, `grep`, `glob`. Не запускай `cat`, `type`, `find`, `npm`
и другие команды вне разрешённого списка.

## Что проверять

- Логику и регрессии: неверные условия и границы, `null`/`undefined`, пустые массивы,
  отсутствующие настройки, гонки и утечки.
- Слои и импорты по `AGENTS.md` и вложенным `AGENTS.md`: `src/app/` — только маршруты
  и композиция; `src/domain/` — без React, БД и нативных модулей; SQL — только
  в `src/db/`; уроки меняются только через стор; после `refresh` вызывается
  `syncNotifications`; `useSQLiteContext()` только внутри `SQLiteProvider`.
- Даты и время: строки `ГГГГ-ММ-ДД`, локальное время, неделя с понедельника,
  границы `start <= now < end`, отсутствие `toISOString()` для дат.
- Стиль проекта: TypeScript strict, именованные экспорты компонентов, импорты через
  `@/`, константы в `src/domain/constants.ts`, один компонент = один файл.
- Тесты: покрыта ли изменённая логика, есть ли тесты на граничные случаи.

Ищи реальные проблемы, а не отклонения от вкуса. Не выдумывай находки ради количества.

## Формат отчёта

Отчёт на русском. Верни его целиком, без сокращений: он нужен для `/fix`.
Ничего не меняй и не применяй.

### Резюме

Что проверено (режим и файлы/папки) и общая оценка.

### Находки

По убыванию: `Blocker`, `High`, `Medium`, `Low`. Для каждой:

- **Blocker — `путь:строка`**
  - Проблема: в чём именно ошибка.
  - Почему важно: последствия для пользователя или данных.
  - Как проверить: шаги, команда или тест.
  - Что исправить: конкретное предложение.

Если находок какого-то уровня нет — не добавляй пустой раздел. Если находок нет
совсем — так и скажи, перечислив, что именно проверил.

### Чего не хватает в тестах

Конкретные сценарии, файлы и предлагаемые тесты. Если что-то не удалось проверить
без запуска приложения или тестов, перечисли это здесь.

### Известные и отложенные проблемы

Не выдавай за новые:

- Баг №1 — `ending` может оказаться длиннее урока (есть `it.failing`-тест).
- Баг №2 — пересечения уроков не обрабатываются.
- Баг №4 — уведомления не пересобираются после отмены урока.
- Баг №5 — гонка загрузки настроек.
- Отложено: №3 (урок через полночь), B4.2 (уведомление нельзя смахнуть),
  B4.3 (фоновая задача/перезагрузка).

Если встретил одну из них — отметь, что она известна, и не считай новой. Если
у известной проблемы появилось новое проявление — опиши именно его.
