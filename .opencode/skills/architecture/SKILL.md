# Architecture — слои и порядок изменений

## Когда применять

- Новая функция или заметное изменение поведения.
- Рефакторинг, перенос кода между слоями.
- Вопрос «куда это положить?», «можно ли здесь вызвать БД/стор?».
- Изменение расчётов дат, времени, расписания или уведомлений.
- Спор об именовании, экспортах, константах.

Не подменяет профильные скилы: SQL и миграции — `db-schema`, zustand — `store`,
тесты — `testing`, UI — `component`.

## Какие AGENTS.md прочитать

Пути от корня проекта.

1. `AGENTS.md` — контекст, стек, команды, текущее состояние.
2. `src/AGENTS.md` — **главный файл по слоям**: схема зависимостей и порядок добавления
   функции. Читать всегда.
3. `AGENTS.md` целевого слоя:
    - `src/domain/AGENTS.md` — типы, даты, расписание, план уведомлений;
    - `src/db/AGENTS.md` — SQL, миграции, kv-store;
    - `src/store/AGENTS.md` — zustand и `refresh`;
    - `src/notifications/AGENTS.md` — каналы и планировщик;
    - `src/hooks/AGENTS.md` — связующие хуки;
    - `src/components/AGENTS.md` — компоненты и палитра;
    - `src/app/AGENTS.md` — маршруты и экраны.
4. `AGENTS_DETAILS.md`, раздел 5 «Архитектура подробнее» — если нужно понять, почему
   решение принято именно так.

Не пересказывай эти файлы в ответе — ссылайся на них.

## Пошаговый порядок

1. **Найди текущее поведение в коде.** Владелец часто правит код сам; пример из прошлого
   ответа может быть устаревшим. Ищи существующий аналог через `grep`/чтение файлов.
2. **Определи слой.** Пользуйся таблицей ниже.
3. **Типы и константы.** Новые типы — `src/domain/types.ts`, константы —
   `src/domain/constants.ts`. Не дублируй числа и цвета по файлам.
4. **Чистая логика — в `src/domain/`.** `now` и `AppSettings` передавай параметрами.
   Никаких `Date.now()`, стора, БД, React и нативных модулей.
5. **Сразу напиши unit-тест** рядом с функцией (`src/domain/<name>.test.ts`).
6. **Данные — в `src/db/`.** SQL только там; наружу camelCase-типы. См. скил `db-schema`.
7. **Изменение данных — через `src/store/`.** Новое действие должно заканчиваться
   `refresh`. См. скил `store`.
8. **Уведомления.** Если меняются тексты или шаги — правь `domain/notificationTexts.ts`
   и `domain/statusTimeline.ts`, а `notifications/scheduler.ts` только вызывает их.
9. **UI.** Компонент — `src/components/`, маршрут — `src/app/`. См. скил `component`.
10. **Проверь направление импортов** и прогони команды из раздела ниже.

## Куда что класть

| Что добавляете                         | Слой                 | Признак правильного места            |
| -------------------------------------- | -------------------- | ------------------------------------ |
| Тип, константа, расчёт, форматирование | `src/domain/`        | тестируется без телефона             |
| SQL, миграция, чтение/запись БД        | `src/db/`            | есть `db: SQLiteDatabase`            |
| Действие, состояние экрана             | `src/store/`         | меняет данные только через `refresh` |
| Канал, триггер, разрешение             | `src/notifications/` | нет текстов и расчёта шагов          |
| Связка UI со стором/навигацией         | `src/hooks/`         | есть React-хук, нет бизнес-логики    |
| Карточка, модалка, поле                | `src/components/`    | данные пропсами, действия из хука    |
| Маршрут, layout, композиция            | `src/app/`           | только `export default` экрана       |

## Шаблон кода

Чистая функция — единственный источник бизнес-правила:

```ts
// src/domain/lessonRules.ts
import type { AppSettings, Lesson } from './types';

export function canStartLesson(lessons: Lesson[], now: Date, settings: AppSettings): boolean {
    // только параметры: без Date.now(), стора, БД, React и expo-*.
    return lessons.some((lesson) => !lesson.cancelled);
}
```

Тест рядом:

```ts
// src/domain/lessonRules.test.ts
import { canStartLesson } from '@/domain/lessonRules';
import { makeLesson } from '../../test/helpers/lessons';

const at = (h: number, m: number) => new Date(2026, 9, 5, h, m);

it('не учитывает отменённые уроки', () => {
    const lessons = [makeLesson({ cancelled: true })];

    expect(canStartLesson(lessons, at(8, 0), settings)).toBe(false);
});
```

Дальше функция подключается по цепочке, без обратных импортов:

```text
domain (правило + тест)
  → db (если нужны данные)
  → store (действие + refresh + syncNotifications)
  → hook/component (данные и вызов действия)
  → app (маршрут/композиция)
```

## Правила, которые нельзя нарушать

- Зависимости идут только сверху вниз; `domain` не импортирует ничего, кроме себя.
- В `domain` нет `react`, `react-native`, `expo-*`, `zustand`, `notifee`.
- SQL — только в `src/db/`; компоненты и экраны SQL не выполняют.
- Изменения уроков — только через действия стора (`saveLesson`, `removeLesson`,
  `copyWeek`), чтобы сработал `refresh`.
- Компоненты не принимают колбэки действий пропсами — берут `useLessonActions()`.
- Настройки в чистые функции передаются параметром; из стора их читает только UI,
  планировщик читает kv-store напрямую.
- Дата — строка `ГГГГ-ММ-ДД`, время — `ЧЧ:ММ`, локальное время, без `toISOString()`.
- Неделя с понедельника; границы урока `start <= now < end`.
- Именованные экспорты везде, `default export` — только экраны в `src/app/`.
- Один компонент/хук/модуль — один файл; имя файла отражает содержимое.

Именование: функции — глагол (`build`, `get`, `validate`, `format`), булевы —
`is/has/can/should`, типы — `PascalCase`, константы — `UPPER_SNAKE_CASE`.

## Чек-лист перед завершением

- [ ] Код лежит в правильном слое, обратных импортов нет.
- [ ] `now`, настройки и уроки приходят параметрами; `Date.now()` только в UI/планировщике.
- [ ] Нет `toISOString()` для дат; форматирование только при выводе.
- [ ] Новые константы — в `domain/constants.ts`, числа не размазаны по коду.
- [ ] У новой логики есть unit-тест; известный баг отмечен `it.failing`, а не скрыт.
- [ ] Изменения данных идут через стор и заканчиваются `refresh`.
- [ ] Экспорты именованные, экран — единственный `default export`.
- [ ] Прочитан AGENTS.md затронутого слоя, правила не разошлись с документацией.

## Команды проверки

```bash
npm run typecheck
npm test
npm run lint

# точечно, пока пишешь
npm test -- src/domain/lessonRules.test.ts
```

Если менялись навигация, уведомления или нативный модуль — нужна ручная проверка на
телефоне в development build; тесты её не заменяют.

## Типичные ошибки

- **Бизнес-логика в компоненте или страте.** Она должна быть в `domain` и покрыта тестом.
- **`Date.now()` внутри чистой функции.** Передавай `now`; иначе тест зависит от часов.
- **`toISOString()` для дат.** Вечером даёт вчерашнюю дату; используй `toDateString`.
- **Прямой `addLesson`/`deleteLesson` из экрана.** Стор не обновится, уведомления не
  пересоберутся.
- **Тексты уведомлений в `src/notifications/`.** Они живут в `domain/notificationTexts.ts`.
- **Новая константа на месте использования.** Перенеси в `domain/constants.ts`.
- **`default export` у компонента.** Ломает принятый стиль и автоподстановку.
- **Новая библиотека без согласования.** Сначала объяснить, зачем, и получить согласие.
- **Доверие к примеру из памяти.** Сверяйся с текущим кодом и AGENTS.md.
