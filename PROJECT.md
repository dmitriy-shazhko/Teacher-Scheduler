# Teacher Schedule — Android-приложение расписания для учителя

> Документ для передачи контекста другому чату с ИИ или агенту. Прочитай его целиком, прежде чем что-либо писать. Раздел 12 содержит инструкции, как со мной (владельцем проекта) работать.

## 1. Цель проекта

Мобильное приложение под **Android** для учителя. Оно хранит расписание уроков по конкретным датам и напоминает о них уведомлениями.

### Требования (от владельца)

1. Составлять расписание на неделю.
2. Для каждого урока указывать: **дату, время начала и конца, класс, кабинет, тему**.
3. **Утром** приходит уведомление: где, во сколько, с кем урок, по какой теме и во сколько он заканчивается.
4. **За 5 минут до конца урока** срабатывает уведомление с **вибрацией** («скоро конец урока»).
5. **После окончания урока** приходит уведомление о начале следующего урока с информацией о нём.
6. Тема урока меняется почти каждую неделю, её нужно легко редактировать.
7. Должна быть возможность **просматривать расписание прошлых недель**.
8. Кнопка **«Скопировать неделю»**: выбрать предыдущую неделю и скопировать её уроки на текущую.
9. Формат даты в интерфейсе: **ДД.ММ.ГГГГ** (например, 25.12.2026).

### Контекст владельца

- Опыт: React (веб). Kotlin не знает, поэтому выбран React Native.
- **Цель двойная:** сделать приложение и **научиться писать на React Native**. Поэтому работаем маленькими шагами с объяснениями (см. раздел 12).
- Общение на русском.
- ОС разработки: Windows (Git Bash, пути вида `src\app\_layout.tsx`). Тестирование на реальном Android-телефоне.

## 3. Принятые архитектурные решения

### 3.1. Каждый урок — отдельная строка с конкретной датой

Рассматривались две модели: «повторяющиеся слоты + экземпляры на даты» и «одна таблица уроков с датами». **Выбрана вторая**, потому что:

- запрос дня или недели тривиален: `WHERE date = ?`;
- правка урока затрагивает **только этот урок**, прошлое неизменно;
- уведомления строятся напрямую из уроков ближайших дней;
- не нужна логика периодов действия слотов.

Цена: расписание повторяется, поэтому есть кнопка **«Скопировать неделю»**. При копировании **отменённые уроки не копируются**, темы очищаются, остальное копируется со сдвигом по дню недели.

### 3.2. Даты и время

- В базе и в стейте дата хранится строкой **`ГГГГ-ММ-ДД`** (`"2026-12-25"`). Она сортируется как текст, работают запросы `date >= ? AND date <= ?`.
- Время хранится строкой **`ЧЧ:ММ`** с ведущим нулём (`"08:30"`). В бизнес-логике (`schedule.ts`) для сравнения и разности переводится в **минуты от начала суток** (`toMinutes`).
- Для пользователя форматируем **только в момент вывода**: `formatDateRu("2026-12-25")` → `"25.12.2026"`.
- **Никогда не использовать `toISOString()`** для дат: он возвращает UTC, и вечером можно получить вчерашнюю дату. Все функции работают в локальном времени.
- Неделя начинается с **понедельника**. `weekday` в JS: воскресенье = 0, поэтому везде есть пересчёт `getDay() === 0 ? 7 : getDay()`.
- **Границы урока согласованы везде:** урок текущий при `start <= now < end`; ровно в `end` он уже прошедший (`end <= now`).

### 3.3. Где что живёт

- **Локальный `useState`**: поля формы урока и `now` на экране «Сегодня» (временные данные одного экрана).
- **Zustand**: список уроков открытой недели (`lessons`) и список уроков **сегодняшнего дня** (`todayLessons`), плюс действия над ними. Он нужен нескольким экранам и будущей синхронизации уведомлений.
- **Прямое обращение к БД** допустимо для разовых чтений (например, `getLessonById` в форме, `countLessonsForWeek` в окне копирования).
- **Все изменения данных идут через стор** (`saveLesson`, `removeLesson`, `copyWeek`), чтобы в одном месте (`refresh`) обновлять и неделю, и «сегодня», и позже вызывать `syncNotifications`.
- **Компоненты** (`LessonCard`, `NowCard`, `DayCard`) не получают колбэки через пропсы (владелец не любит prop drilling). Они берут действия из хука `useLessonActions`, а пропсами получают только данные.

### 3.4. Уведомления

Главный принцип: **одна функция `syncNotifications(db)`**, которая полностью пересобирает запланированные уведомления из базы: отменяет все старые, планирует новые на **скользящее окно 7 дней вперёд**. Тема зависит от даты, поэтому повторяющихся уведомлений нет, только разовые.

Вызывается:

- после любого сохранения, удаления или копирования уроков (внутри `refresh` в сторе);
- при запуске приложения и при возврате из фона (`AppState`);
- в фоновой задаче раз в сутки (необязательно, не гарантируется на всех прошивках).

Тексты уведомлений строятся **чистыми функциями в `src/domain/`** (без React, без `expo-notifications`, без БД), а `scheduler.ts` только вызывает их и планирует.

**Каналы Android** (создаются в `src/notifications/channels.ts`, константы в `CHANNELS`):

| Ключ         | id канала        | Важность | Особенности                                      |
| ------------ | ---------------- | -------- | ------------------------------------------------ |
| `endingSoon` | `ending-soon-v1` | HIGH     | `vibrationPattern: [0, 400, 200, 400, 200, 400]` |
| `nextLesson` | `next-lesson`    | HIGH     | начало следующего урока                          |

Вибрацию и звук канала **нельзя изменить после создания**. Чтобы поменять паттерн, создаётся новый канал (`ending-soon-v2`), константа меняется, старый удаляется через `deleteNotificationChannelAsync`. Поэтому в id у вибрирующего канала суффикс версии.

**Инициализация при старте:** `initNotifications()` в `src/notifications/init.ts` (сначала `setupChannels()`, потом `ensureNotificationPermission()`: на Android 13+ запрос разрешения показывается после создания канала). Вызывается из `useEffect(() => { initNotifications(); }, [])` в `_layout.tsx`. Позже сюда добавятся `syncNotifications` и подписка на `AppState`; если понадобится `useSQLiteContext()`, возможно, стоит вынести в хук.

**Показ на переднем плане:** `Notifications.setNotificationHandler(...)` вызывается один раз на уровне модуля в `_layout.tsx` (`shouldPlaySound: false`, `shouldSetBadge: false`, `shouldShowBanner: true`, `shouldShowList: true`). Если TypeScript не принимает названия полей, свериться с типами установленной версии `expo-notifications`.

**Точные будильники** (`SCHEDULE_EXACT_ALARM`) сознательно отложены: сначала проверить точность срабатывания без них на реальных уроках, добавить, если будет опаздывать.

## 4. Структура проекта

Важно: папка **`app` лежит внутри `src`** (так создаёт актуальный шаблон Expo). Алиас импортов **`@/`** указывает на `src/`. Схема приложения (`scheme` в `app.json`): `scheduler`.

```
src/
  app/                          # только экраны (каждый файл = маршрут)
    _layout.tsx                 # SQLiteProvider + Stack, initNotifications, setNotificationHandler
    lesson.tsx                  # форма создания/редактирования урока
    (tabs)/
      index.tsx                 # <Redirect href='/today' /> (иначе "Unmatched Route scheduler:///")
      _layout.tsx               # нижние вкладки: Сегодня / Неделя / Настройки
      today.tsx                 # готов: текущий/следующий урок, секции
      week.tsx                  # экран недели
      settings.tsx              # заглушка
  components/
    LessonCard.tsx
    NowCard.tsx
    DayCard.tsx
    CopyLessonsModal.tsx
    PickerField.tsx
  db/
    migrate.ts
    lessons.ts
  domain/
    types.ts
    dates.ts
    constants.ts                # WEEKDAYS, REFRESH_LESSONS_MS
    schedule.ts                 # getCurrentAndNextLessons, lessonIsPassed, formatDuration, toMinutes
  hooks/
    useLessonActions.ts
  notifications/
    channels.ts                 # CHANNELS, setupChannels
    permissions.ts              # ensureNotificationPermission
    init.ts                     # initNotifications
    scheduler.ts                # (будет) syncNotifications
  store/
    lessonsStore.ts
```

Правила:

- В `src/app/` лежат **только экраны** с `export default`. Компоненты внутрь не класть: expo-router воспримет их как маршруты.
- Компоненты: именованный экспорт, один компонент = один файл, стили в том же файле.
- Файлы уведомлений живут в `src/notifications/`.

### Навигация

- `app/_layout.tsx`: `SQLiteProvider databaseName="schedule.db" onInit={migrateDb}` оборачивает `Stack` с `headerShown: false`. Есть `export const unstable_settings = { initialRouteName: "(tabs)" }`.
- `app/index.tsx`: редирект с `/` на `/today`. Нужен, потому что dev-клиент открывает приложение по ссылке `scheduler:///`, а маршрута для корня иначе нет.
- `app/(tabs)/_layout.tsx`: `Tabs` с экранами `today`, `week`, `settings`; иконки Ionicons (`today-outline`, `calendar-outline`, `settings-outline`).
- `lesson` открывается через `router.push({ pathname: '/lesson', params: { date } })` для нового урока или `{ id: String(id) }` для редактирования. Режим формы определяется по наличию `id`.

## 5. Модель данных

### Тип (`src/domain/types.ts`)

```ts
export type Lesson = {
    id: number;
    date: string; // "2026-10-05"
    startTime: string; // "08:30"
    endTime: string; // "09:15"
    className: string;
    room: string;
    topic: string; // пусто, пока не вписана
    cancelled: boolean;
};

// для окна копирования недели
export type CopyLessonsSource = { start: Date; count: number };
```

### Схема SQLite (`src/db/migrate.ts`)

Версионирование через `PRAGMA user_version`. Текущая версия схемы: **1**.

```sql
CREATE TABLE lessons (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL,
  start_time TEXT NOT NULL,
  end_time TEXT NOT NULL,
  class_name TEXT NOT NULL,
  room TEXT NOT NULL,
  topic TEXT NOT NULL DEFAULT '',
  cancelled INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_lessons_date ON lessons(date);
```

Схема миграции: блоки `if (current < N) { ... }` идут по порядку, в конце `PRAGMA user_version = DATABASE_VERSION`. Для новой таблицы или колонки нужно поднять `DATABASE_VERSION` и добавить новый блок `if (current < N)`. Не менять существующие блоки.

### Функции БД (`src/db/lessons.ts`)

В БД имена в `snake_case`, в коде `camelCase`; перевод делает `rowToLesson`. Все значения в SQL подставляются через `?`.

| Функция                                    | Назначение                                                               |
| ------------------------------------------ | ------------------------------------------------------------------------ |
| `getLessonsForDate(db, date: Date)`        | уроки одного дня                                                         |
| `getLessonsForWeek(db, monday: Date)`      | уроки недели (пн–вс), по дате и времени                                  |
| `countLessonsForWeek(db, monday)`          | количество уроков недели (для окна копирования)                          |
| `getLessonById(db, id)`                    | один урок или `null`                                                     |
| `addLesson(db, lesson)`                    | добавить                                                                 |
| `updateLesson(db, id, lesson)`             | изменить только этот урок                                                |
| `deleteLesson(db, id)`                     | удалить (физически)                                                      |
| `copyWeek(db, sourceMonday, targetMonday)` | копирование недели в транзакции; темы очищаются, отменённые пропускаются |

Для `syncNotifications` понадобится запрос уроков на диапазон дат (на 7 дней вперёд от сегодня); `getLessonsForWeek` для этого не подходит, лучше добавить `getLessonsForRange(db, from, to)`.

### Хелперы дат (`src/domain/dates.ts`)

`toDateString(Date)`, `parseDate(string)`, `addDays(Date, n)`, `startOfWeek(Date)` (понедельник), `daysBetween(a, b)`, `formatShort(Date)` → «5 окт», `formatWeek(monday)` → «5 окт – 11 окт», `formatDateRu(string)` → «25.12.2026», `timeToDate("08:30")`, `dateToTime(Date)`.

### Логика расписания (`src/domain/schedule.ts`)

Чистые функции без React и БД:

- `toMinutes("08:30")` → `510`;
- `getCurrentAndNextLessons(lessons, now)` → `{ current, next, minutesLeft, minutesToNext }`; отменённые игнорируются, текущий: `start <= now < end`, следующий: первый неотменённый с `start > now`; `lessons` должны быть уроками **одного дня** с `now`;
- `lessonIsPassed(lesson, now)` → `end <= now`;
- `formatDuration(minutes)` → «35 мин», «1 ч 15 мин», «2 ч».

### Zustand (`src/store/lessonsStore.ts`)

Состояние: `weekStart: Date | null`, `lessons: Lesson[]` (открытая неделя), `todayLessons: Lesson[]` (сегодня).
Действия: `loadWeek(db, weekStart)`, `loadToday(db)`, `removeLesson(db, id)`, `saveLesson(db, id | null, data)`, `copyWeek(db, source, target)`.

Внутренний хелпер `refresh(db)` перезагружает открытую неделю (если `weekStart` задан) и «сегодня». Все изменяющие действия заканчиваются вызовом `refresh`. **Сюда же добавится `syncNotifications(db)`**: одна строка покроет сохранение, удаление и копирование. Функции БД импортируются с псевдонимами (`addLesson as dbAddLesson`, `copyWeek as dbCopyWeek`), чтобы не путаться с одноимёнными действиями стора.

### Хук (`src/hooks/useLessonActions.ts`)

Возвращает `{ addLesson(dateStr), openLesson(id), confirmRemove(id) }`. Внутри навигация через `router`, подтверждение удаления через `Alert.alert`, само удаление через стор.

## 6. Экраны

### «Неделя» (`week.tsx`) — готов

- Переключатель недель ‹ ›, подпись «5 окт – 11 окт», кнопка «Текущая неделя».
- Для каждого из 7 дней `DayCard` с заголовком, кнопкой «＋» и списком `LessonCard`.
- Кнопка «Скопировать неделю» открывает `CopyLessonsModal`: ищет в 8 предыдущих неделях те, где есть уроки (последовательные `await countLessonsForWeek`; распараллеливать нет смысла, `expo-sqlite` работает через одно соединение), показывает список с количеством, при выборе копирует. Если на целевой неделе уже есть уроки, спрашивает подтверждение.
- Список загружается через `useFocusEffect(useCallback(() => { load(); }, [load]))`, потому что вкладки не размонтируются при переключении.
- Копирование идёт через действие стора `copyWeek` (чтобы обновлялось «сегодня» и позже уведомления).
- Временная кнопка «+ Тестовый урок» (`addTest`) должна быть удалена.

### «Урок» (`lesson.tsx`) — готов

- Поля: дата, начало, конец, класс, кабинет, тема (многострочное), переключатель «Урок отменён».
- Дата и время выбираются системными пикерами через `PickerField` (`DateTimePickerAndroid.open`). Состояние форм остаётся строками. Дата показывается как `ДД.ММ.ГГГГ` (`formatDateRu`), хранится как `ГГГГ-ММ-ДД`.
- При смене начала конец автоматически ставится +45 минут (можно поправить вручную).
- Валидация: конец позже начала, класс не пустой.
- Сохранение идёт через `saveLesson` из Zustand, затем `router.back()`.

### «Сегодня» (`today.tsx`) — готов

- Данные из стора (`todayLessons`, `loadToday`). `now` в локальном `useState`.
- `useFocusEffect` + `setInterval` (`REFRESH_LESSONS_MS`, 30 секунд): на каждом тике обновляется `now` и перезагружаются уроки (так подхватываются правки и смена суток). Таймер гасится при уходе с вкладки.
- Один прокручиваемый `SectionList`: в `ListHeaderComponent` карточки `NowCard` («Текущий урок» с акцентным фоном `#4a4ae0` и «осталось …» до конца; «Следующий урок» с «осталось … до начала»), ниже секции «Остальные уроки», «Прошедшие уроки», «Отмененные уроки» (пустые секции отфильтрованы).
- Состояния: уроков нет вообще → «Сегодня уроков нет» (`SectionList` не рисуется); уроки есть, но ни текущего, ни следующего → «Уроков сегодня больше нет».
- Известная мелочь: если на сегодня только отменённые уроки, всё равно покажется «Уроков сегодня больше нет». Можно заменить условие `lessons.length > 0` на `lessons.some((l) => !l.cancelled)`.

### Компоненты карточек

- `LessonCard`: белый фон, класс синим (`#056ccc`); у отменённого урока серый фон `#cfcfcf` и серый текст. Нажатие открывает форму, долгое нажатие вызывает подтверждение удаления.
- `NowCard`: пропсы `label`, `hint`, `lesson`, `accent?`. В RN цвет текста не наследуется, поэтому на светлом тексте стоит стиль на каждом `<Text>`.

## 9. Подводные камни и найденные грабли (чтобы не повторять)

- **Любой текст должен быть внутри `<Text>`.** Лишняя `;` между тегами в JSX даёт ошибку «Text strings must be rendered within a <Text> component»: `<Stack ... />;` внутри провайдера.
- **`{x && <Comp/>}` с числом:** если `x === 0`, React Native попытается нарисовать `0` как текст вне `<Text>` и упадёт. Сравнивать явно (`x !== null`, `x > 0`).
- **`tabBarIcon: () => { <Icon/> }`**: с фигурными скобками нужен `return`, иначе иконка не рисуется. Либо `=> ( <Icon/> )`.
- **`useFocusEffect` требует колбэк в `useCallback`**, иначе бесконечный цикл. Нужен вместо `useEffect` на вкладках, потому что вкладки не размонтируются. Таймеры (`setInterval`) внутри него обязательно очищать в возвращаемой функции.
- **Типы маршрутов expo-router** генерируются при старте сервера: после добавления нового экрана перезапустить `npx expo start --dev-client -c`.
- **«Unmatched Route, Page could not be found `scheduler:///`»** в dev-клиенте: нет маршрута для `/`. Решение: `src/app/index.tsx` с `<Redirect href='/today' />`. В Expo Go это не проявлялось.
- **`key` ставится на элемент в массиве** (в `week.tsx` на `<DayCard key=...>`), а не внутри самого компонента.
- **Старая ошибка**: в `addTest` стоял `addDays(weekStart, -Math.floor(...))` с минусом, и уроки уходили в прошлую неделю. Функция должна быть удалена.
- **Android 12+:** точное срабатывание уведомлений требует разрешения на точные будильники.
- **Каналы Android неизменяемы** по звуку и вибрации после создания. Менять паттерн только созданием канала с новым id.
- **Android 13+:** запрос `POST_NOTIFICATIONS` показывается, только когда канал уже создан, поэтому порядок в `initNotifications`: каналы, затем разрешение.
- **Нативные пакеты требуют пересборки dev-клиента.** Одного `npm install` мало: старый APK не содержит нового нативного кода. JS-изменения пересборки не требуют.
- **Данные SQLite в dev-сборке отдельные** от Expo Go (другое приложение): тестовые уроки нужно создавать заново.
- **Цвет текста в RN не наследуется** от родителя: красить каждый `<Text>` (исключение: `<Text>` внутри `<Text>`).
- **Вложенные вертикальные списки нельзя** (`FlatList` в `FlatList`/`ScrollView`): для нескольких секций использовать `SectionList` или `ListHeaderComponent`/`ListFooterComponent`.
- `async` нельзя передавать напрямую в `useEffect`: использовать `(async () => { ... })()` либо вызывать отдельную async-функцию с фигурными скобками `useEffect(() => { fn(); }, [])` (стрелка без скобок вернула бы Promise).
- Пикер даты `DateTimePickerAndroid.open` работает только на Android (цель проекта именно она).
- `expo-doctor` может ругаться на патч-версии внутри SDK: это не ошибка, обновляется `npx expo install --fix`.

## 10. Запуск и команды

```bash
npm install                          # зависимости
npx expo start --dev-client          # dev-сервер для установленного development build
npx expo start --dev-client -c       # то же с очисткой кэша (после новых маршрутов)
npx expo start --tunnel              # если Wi-Fi мешает подключению телефона
npx expo install <пакет>             # установка библиотек в версиях, совместимых с Expo
npx expo install --check             # сверка версий пакетов с SDK
npx expo install --fix               # привести версии к ожидаемым
npx expo-doctor                      # диагностика проекта
eas build --profile development --platform android   # пересборка dev-клиента (после нативных пакетов)
eas build:list                       # история сборок
```

Телефон и компьютер должны быть в одной Wi-Fi сети. Для установленных нативных пакетов нужна пересборка dev-клиента, для JS-кода нет.

## 11. Соглашения по коду

- TypeScript, функциональные компоненты, именованный экспорт компонентов, `default export` только у экранов в `src/app/`.
- Импорты через алиас `@/…`.
- Одинарные кавычки (в том числе в JSX-атрибутах), отступ 4 пробела (так форматирует владелец).
- Стили: `StyleSheet.create` в конце того же файла. Акцентный цвет `#4a4ae0`, серый `#888`; карточки уроков белые (`#fff`), класс синим `#056ccc`, отменённые `#cfcfcf` / `#8f8f8f`; акцентная карточка «Текущий урок» `#4a4ae0` с белым текстом.
- Бизнес-логика (текущий/следующий урок, формирование текстов уведомлений) выносится в чистые функции в `src/domain/`, без React и без БД.
- Работа с БД только в `src/db/`; наружу отдаёт camelCase-типы.
- Работа с уведомлениями только в `src/notifications/`; тексты уведомлений собираются в `src/domain/`.
- Любое изменение уроков идёт через действия стора, не напрямую через БД.
- Машинный формат даты (`ГГГГ-ММ-ДД`) везде внутри, форматирование только при выводе.
- Константы (интервалы, названия дней) в `src/domain/constants.ts`.
